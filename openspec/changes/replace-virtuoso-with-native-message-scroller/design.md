# Design: replace Virtuoso with the native Message Scroller

## Context

MessageList, Header hover-card lists, and the Footer `@` autocomplete previously rendered through `react-virtuoso`. Its retained internal scroll commands conflicted with product-owned scroll behavior, and its virtual DOM hid real rows from measurement and accessibility surfaces. The replacement uses real DOM for all three lists.

## Decisions

- **Behavior engine**: the official shadcn registry `message-scroller` item, vendored as `src/components/ui/message-scroller.tsx` with only import-alias/Tailwind adaptations. The scroll engine remains `@shadcn/react/message-scroller`; WebChat adds no parallel engine.
- **Chat semantics layer**: the primitive owns initial end presentation (`defaultScrollPosition="end"`), manual scroll intent (wheel/touch/keyboard), and prepend anchoring (`preserveScrollOnPrepend`). MessageList adds only what the primitive does not carry: one current follow authorization for an at-bottom tail append, and off-bottom arrival counting behind one recovery action. The authorization carries the tail generation and last commanded scroll height; while it is unsettled, self-caused transient off-bottom geometry (its own motion or an intrinsic reserve converting to a taller real row mid-travel) can neither count nor cancel it; a newer tail commit or a native scroll event retargets only on a strictly advanced scroll height/tail generation; native `scrollend` settles it (bottom retires, otherwise one deduped smooth command to the current max); real wheel/touch/navigation-key/scrollbar-drag intent cancels it while pointer/click/selection and programmatic scroll events never do. The recovery action's visibility is gated independently of the engine's 8px edge: it appears iff the exact bottom distance exceeds 0.5× the current viewport client height, hidden at or below it, with the arrival count retained internally at any distance and never overriding the gate; the distance is recomputed on commit, native scroll/scrollend, and shell/content resize. Exactly one app-side ResizeObserver observes the viewport and content: besides the gate refresh, it reconciles a strict post-settle scroll-height growth with one deduped auto end command per new height/tail generation, only while the position physically sits at the previous bottom and no current authorization owns retargeting; manual off-bottom reading is never reclaimed, later tails count normally, and the observer callback cannot self-loop or duplicate the same generation. No timer, debounce, polling, retry, or animation-frame loop is used.
- **Sole scroll owner**: the message list composes the repository shadcn `ScrollArea` through its backward-compatible `viewport` render-prop seam, and the engine Viewport renders with the repository's Radix Viewport as its `render` target through a minimal Owner-authorized dependency patch to the engine Viewport (mirroring the engine's own Button `render` prop; patch scope is the artifact, package-manager registration, and lock identity only). One DOM element owns overflow, the repository `ScrollBar`, Radix scrollbar measurement, the engine viewport ref, every geometry read, and every scroll command. No native overflow owner, nested viewport, second geometry source, or alternate scrollbar exists.
- **Row-level optimization**: every repeated row carries `content-visibility: auto` with a stable `contain-intrinsic-size` (message rows 104px fallback keyed by `auto` so measured layout is never altered — the minimal value passing the frozen real-browser CSS matrix across short-history zero-scroll, 24/800-row initial end, resize/follow, and off-bottom preserve; header room rows 56px; header user rows 28px; footer options 16px content box + 12px padding = the existing 28px option-row outer geometry, probe-verified: skipped outer equals the intrinsic fallback plus padding, and 16px yields 28px rows at N=100). No container-level substitute.
- **Footer keyboard**: selection state stays in the component; the active option uses native `scrollIntoView({ block: 'nearest' })` instead of the removed Virtuoso handle.
